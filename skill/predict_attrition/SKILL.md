# 퇴사위험 학습·평가와 신규 예측

숫자는 엔진 산출물에서만 읽는다. 현재 데이터만으로 미래 예측 성능을 주장하지 않는다.

## 요청 분기

1. **과거 스냅샷과 퇴사 이력:** `reference/training.md`를 읽고 학습 manifest를 구성한다. 질문의 퇴사 유형, 기간, HR 처리 용량 K, 학습/검증/미래 평가 기간을 명시한다.
2. **현재 재직자와 고정 모델:** 모델의 회사·유형·기간이 요청과 일치하는지 엔진이 검사한다. 현재 라벨은 사용하지 않고 고정 모델로 점수를 만든다.
3. **현재 파일만 있음:** 예측에 필요한 과거 자료/모델이 없음을 알린다. 사용자가 현재 신호 진단을 요청했을 때만 `--mode heuristic`을 사용한다. 예측 오류를 진단 성공으로 대체하지 않는다.
4. **이미 계산한 결과 후속 질문:** 저장된 결과를 조회한다. 표시 필터만 적용하며 재학습하지 않는다.

## 학습

```bash
python <스킬 폴더>/scripts/predict_attrition.py --train-manifest history.json --out <모델 폴더>
```

입력 계약과 manifest 예시는 `reference/training.md`, 라벨 조건은 `reference/labels.md`.
`evaluation.json`, `candidate_comparison.csv`, `future_predictions.csv`, `model.joblib`를 만든다.
검증 기간의 평균 Precision@K로 후보를 선택하며 미래 평가 구간은 선택에 쓰지 않는다.
합성 데이터는 실행 경로 확인용이다. 실제 예측 정확도가 검증됐다고 말하지 않는다.

## 현재 예측

```bash
python <스킬 폴더>/scripts/predict_attrition.py --input <현재.xlsx> --model-artifact <모델 폴더>/model.joblib --target "자발적 퇴사" --horizon-days 90 --out <출력 폴더>
```

직접 생성하거나 신뢰할 수 있는 모델 파일만 사용한다. 모델과 질문이 다르면 해당 질문의 모델을 학습한다. 기준일이 모델 평가의 관측 종료일 이후인지 검사한다.
`--spec`에는 모델 경로·해시가 보존된다. 모델이 없거나 바뀌면 오류이며 진단으로 내려가지 않는다.
`--filter`로 조회 모집단을 좁혀도 고정 모델의 회사 전체 순위·밴드 기준은 유지한다.

## 결과 설명

먼저 대상·기간·기준일, 예측/진단 구분, 모델의 미래 평가 기간과 상위 K명 적중률을 간결하게 설명한다. 합성 데이터 또는 기준선 미개선은 명시한다. 직원 목록 요청에는 실제 값과 비교 기준을 붙인다.
점수는 **확인 우선순위용이며 보정된 퇴사 확률이 아니다**. 0.7을 퇴사 확률 70%라고 말하지 않는다.
유지 우선순위는 HR이 별도 지정하는 업무 판단이다. 퇴사위험 점수에 합치지 않는다.
데이터·가설·검증 상세는 요청 시 펼친다. 매번 여섯 단계 전체를 길게 반복하지 않는다.
예측 기여와 조치의 인과 효과를 구분한다. 민감 속성·병가·설문 미응답은 개인 예측 입력으로 사용하지 않는다.

대시보드는 `/make_dashboard`에 결과 xlsx와 같은 회사·기준일의 원본을 전달한다.
